# S11/S12 bounded incremental ledger and operational diagnostics
Position accounting now maintains a per-pool/owner/position archive pointer index, alternating recent head pages and older cursor pages until the bounded retention budget (eight pages, ten signatures per page) or observed short/empty page. Repeated whole page subsets replaced; T15 reprocesses original source files, deduplicates signatures and rejects conflicts. Previous manifest hashes checked before reuse, and the reconciler uses shared transaction-version normalization. Partial page does not advance the cursor. A disjoint head, partial sample or retention truncation conservatively blocks clean valuation windows; sticky gaps are not automatically cleared. Index publishes only after successful bounded ledger projection and report persistence. No lifetime completeness or actual PnL claim; old raw files are retained. A historical archive index lock may require operator inspection after a crash; never remove an active lock. Eight retained pages is a deliberately bounded starting point, not complete incremental lifecycle coverage.
Terminal failure events include request ID, stable error code, duration, status; collector failure events include stream and duration. No URLs, request bodies, raw stderr or remote messages logged. Logs are stdout; persistent rotation is external. Run node research/live/archive-audit.mjs for bounded read-only inventory (50k entries, 10s, 5GiB warning); skips symlinks, reports scanned scope, no deletion or quota enforcement. No automatic GC.
Run node --test research/live/incremental-ledger.test.mjs research/live/diagnostic-log.test.mjs and full verifier. Local archive IO, V1 real transaction and multi-page T15 performance not yet verified; timeout remains bounded and can block busy histories.
