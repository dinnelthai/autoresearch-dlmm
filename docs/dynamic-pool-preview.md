# Dynamic pool observation
After updating and restarting the terminal once, entering a valid alternate pool address starts a bounded read-only market capture through the existing state-service --once --market-only path. The configured primary pool and its research/monitoring state are untouched. Alternate state is stored under data/live-preview/<pool>, not data/live/<pool>. One alternate capture is allowed at a time; subsequent polls retry after a 30-second cooldown. The existing protocol/identity/coverage checks apply, so unsupported tokens or missing accounts still block data. Configure dynamicCapture.provider and dynamicCapture.idl if your local RPC provider label or IDL path differs. SOLANA_RPC_URL is inherited from the terminal process. Market history and wallet observation use the selected pool. Alternate pool strategies, position monitoring and transaction execution remain blocked until separately configured; this is a read-only preview, not automatic research onboarding.

Local checks: run node research/live/verify-offline.mjs; start existing terminal; choose a second supported pool; observe scoped state at /api/terminal/state?pool=<address>; switch back and verify the primary state and monitor remain intact. Live acceptance has not been performed by this commit.
