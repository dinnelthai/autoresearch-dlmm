# P01/P02 capture bridge and swap evidence classification
Run existing state-service with the desired mainnet pool, then node research/live/paper-record.mjs --pool ADDRESS --watch --interval 30. Recorder reads finalized collector snapshots, checks accounts hash, re-runs pinned IDL transaction decoding (including indexed signature / tx / block evidence), and stores collector state + decoded evidence under data/paper-captures/<pool>/<hash>.json; bounded 256-pointer index, original evidence preserved, disjoint head and partial coverage sticky. It does not produce a reviewed sample or independently certify coverage. Polling may miss intermediate state versions. Each changed snapshot can be large; archive-audit includes these directories. No RPC calls by recorder, no wallet or signing.
Meteora official event reference https://github.com/MeteoraAg/docs/blob/main/developer-guides/dlmm/program/events.mdx documents Swap and Swap2Evt compatibility and total amounts/fees, not per-bin allocations. Unique single-call legacy/rich twins with matching common fields may be collapsed; ambiguity remains blocked. Same start/end bin, rich fee fields and consistent fee side can yield single-bin fee candidates ONLY; pre-transaction liquidity, principal and transfer reconciliation still required. Cross-bin swaps remain raw evidence. No output marks PER_BIN_RECONCILED; paper-run cannot consume these as fills. P01 first capture bridge implemented, P02 partial. Next obtain per-transaction account deltas or exact replay on protocol state; independently reviewed market/reference/coverage events also required. Native decoder and live service tests not executed. Run node --test research/live/paper-event-core.test.mjs and verify-offline.mjs.
