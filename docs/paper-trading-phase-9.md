# P19 configured multi-pool paper experiments
Main pool plus up to eight existing researchPools. Configure separate reviewed evidence paths using paperReviews in terminal config, e.g. {"paperReviews":{"<configured pool>":"data/reviews/that-pool.json"}}; primary uses cfg.review. No review sharing or fallback to the main pool. Each pool uses its own existing state-service collector under data/live/<pool>/state.json. No collector is launched by paper manager; no arbitrary preview pools admitted. Each pool has independent paper-auto/<pool>/active.json, checkpoint, wallet, risk and writer lock. One active experiment per pool. Global scheduler at most two concurrent pool updates, skips overlapping cycles; slow capture may delay later pools, gap checks remain strict. Opening still uses existing analysis lease and reviewed preview. Separate paper-context endpoint for start (read-only review binding), paper-pools endpoint for compact cross-pool status, explicit pool for pause. Existing actual position/strategy review routes unchanged. UI multi-pool overview and scope-specific controls; no ranking or total PnL across incomparable windows. Native HTTP/Node/browser/mainnet not executed. Old backend fingerprint prevents silently resuming previous code's experiments. Pause old experiment before starting a new one.
